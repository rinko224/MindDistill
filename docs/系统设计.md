# 系统设计

## 核心架构概览

本系统采用前后端分离的架构，后端提供 RESTful API，前端采用 React 构建单页面应用 (SPA)。

```text
┌─────────────────────────────────────────────────────────────┐
│                         前端 (React SPA)                    │
│    教材管理 / 知识图谱展示 / RAG问答 / 报告生成 / 教师干预      │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTP / REST
┌──────────────────────────────▼──────────────────────────────┐
│                         后端 (FastAPI)                      │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                     API 路由层 (routers/)             │  │
│  └───────────────────────────┬───────────────────────────┘  │
│                              │                              │
│  ┌───────────────────────────▼───────────────────────────┐  │
│  │                    核心业务逻辑层 (services/)         │  │
│  │                                                       │  │
│  │  ├─ ParserService       : 多格式教材文档解析          │  │
│  │  ├─ GraphBuilderService : 基于 LLM 的知识点提取       │  │
│  │  ├─ MergerService       : 跨教材图谱聚类与合并        │  │
│  │  ├─ RAGService          : 向量化分块与检索增强生成    │  │
│  │  ├─ ChatService         : LLM 意图识别与决策干预      │  │
│  │  └─ ReportService       : 整合数据统计与 Markdown 生成│  │
│  └───────────────────────────┬───────────────────────────┘  │
│                              │                              │
│  ┌───────────────────────────▼───────────────────────────┐  │
│  │                     数据与工具层                      │  │
│  │                                                       │  │
│  │  ├─ LLMClient        : 封装大模型接口调用             │  │
│  │  ├─ EmbeddingService : 本地文本向量化                 │  │
│  │  └─ StorageService   : JSON 内存/本地持久化管理       │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 数据存储设计
由于黑客松时间限制与轻量化部署要求，系统未引入复杂的外部数据库。
- **文件存储**: 原始上传文件存储于 `data/uploaded/`。
- **图谱存储**: 解析结构和节点边关系序列化存放在 `data/books.json` 和 `data/graphs/` 中。
- **向量存储**: 使用轻量级本地向量数据库 `ChromaDB`，持久化于 `data/vectors/`。

## API 接口设计
| 请求方式 | 路由路径 | 功能说明 |
|---|---|---|
| POST | `/api/upload/` | 批量上传多格式教材文件 |
| GET  | `/api/upload/` | 获取已上传的教材列表 |
| DELETE| `/api/upload/{book_id}` | 删除指定教材及其附属缓存、向量索引 |
| POST | `/api/parse/{book_id}` | 触发教材异步结构化解析 |
| GET  | `/api/parse/{book_id}/status` | 查询解析状态 |
| POST | `/api/graph/build/{book_id}` | 触发单本教材的知识点提取与图谱构建 |
| POST | `/api/graph/build_all` | 一键批量构建所有已解析教材的图谱 |
| GET  | `/api/graph/{book_id}` | 获取单本教材的图谱数据 |
| GET  | `/api/graph/merged` | 获取跨教材合并后的全局图谱数据 |
| POST | `/api/merge/` | 触发相似度计算与跨教材整合决策 |
| GET  | `/api/merge/decisions` | 查看系统的整合决策列表 |
| GET  | `/api/merge/result` | 查看整合统计结果 |
| POST | `/api/rag/index` | 构建全局 RAG 向量索引 |
| POST | `/api/rag/query` | 发起带引用的精准 RAG 问答 |
| GET  | `/api/rag/status` | 查询向量索引的准备状态 |
| POST | `/api/chat/` | 教师自然语言对话（可干预合并决策） |
| POST | `/api/report/generate` | 自动生成整合统计报告 Markdown |

## 技术选型依据
- **FastAPI**: 异步支持极佳，极大地提高了并发请求 LLM 的吞吐量，且自带详尽的 API 文档。
- **React**: 组件化开发高效，契合单页面多面板的业务场景。
- **ECharts**: 处理知识图谱的力导向图具有出色的性能，相比 d3.js 开发成本更低。
- **ChromaDB**: 纯 Python 编写的本地向量库，无需额外部署 docker 容器。
- **Sentence-Transformers**: 在本地进行 Embedding 计算，不仅速度快、免 API 费用，且支持重叠式 Chunk 向量化。
